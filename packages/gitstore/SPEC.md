# gitstore

## Specs

### GIT-001
Repository discovery MUST work from a checkout or its nested directory and return the checkout root, worktree Git directory and common Git directory as canonical absolute paths. Linked worktrees MUST have distinct roots and Git directories but share their common Git directory. Non-repositories MUST return an error. Inspection MUST NOT create branches, change refs, fetch or push.

### GIT-002
Base resolution MUST use the configured remote (default origin) and configured branch; when the branch is omitted it MUST use that remote's locally known symbolic default, falling back to main. It MUST prefer an existing refs/remotes/<remote>/<base> over refs/heads/<base>, otherwise return the local ref name even when absent. It MUST NOT contact a remote. Branch names containing slashes MUST be retained.

### GIT-003
Clean-tree inspection MUST detect tracked staged or unstaged edits, deletions and untracked files, while ignoring ignored files. Worktree diffs against an explicit local commit MUST include staged and unstaged additions/modifications/deletions, untracked files and renames with old and new paths. Spaces, tabs and newlines in filenames MUST be preserved. Results MUST be deterministic and invalid Git roots or revision arguments MUST return errors rather than empty success.

### GIT-004
Safe path resolution MUST accept only nonempty repository-relative forward-slash paths without absolute roots, drive prefixes, dot/traversal components, repeated/trailing slashes, backslashes or NUL. It MUST return an absolute path inside the canonical root, allow nonexistent descendants and internal symlinks, and reject existing or ancestor symlinks escaping the root, including sibling paths sharing its string prefix. It MUST NOT create or modify files.

### GIT-005
Run MUST execute exactly the supplied executable and argument vector in dir, without shell expansion, and collect complete stdout and stderr into Output while returning the actual exit code and a non-nil Err for a nonzero exit. Successful execution MUST return Exit 0 and nil Err. It MUST inherit the parent environment, apply supplied KEY=value overrides with the last entry for each key winning (including empty values and values containing equals signs), preserve all caller inputs, and leave the caller's working directory and environment unchanged. Empty argv, an empty executable, nil context, malformed environment overrides, nonexistent working directories and launch failures MUST return Exit 2 with a useful non-nil Err without launching a fallback executable. Long output MUST be drained without deadlock or truncation.

### GIT-006
A context already cancelled or expired before Run MUST prevent process startup, return Exit -1 and an Err matching the context cancellation/deadline via errors.Is. Cancellation or deadline during execution MUST terminate the entire spawned process tree on supported platforms, including children and grandchildren that retain output streams, return promptly with Exit -1 and the matching context Err, and retain output emitted before termination. Descendants MUST NOT survive to perform delayed writes after Run returns. Cancellation MUST leave unrelated processes alive, including when the calling executable is instrumented for race detection. Ordinary successful and failing process termination MUST remain distinguishable from context termination.

### GIT-007
Independent Run calls MUST NOT share captured output or cancellation state, even when overlapping. Run MUST NOT mutate caller argv or override slices, including backing storage beyond their lengths, or the parent environment/current directory. Empty or invalid calls and pre-cancelled calls MUST leave no process-created marker. Invalid inputs and completed successful, failed or cancelled calls MUST NOT poison a later valid call. Process tests MUST use local bounded helpers and no agent/bootstrap/network dependency.

### GIT-008
Capture MUST execute exactly the supplied executable/argument vector in dir without shell expansion and return complete byte-exact stdout and stderr separately in Stdout and Stderr, including empty streams, NUL/non-UTF8 bytes, long output and concurrently emitted streams, without truncation or deadlock. It MUST inherit the parent environment and apply KEY=value overrides with last entry winning, preserving empty values and equals signs; Windows keys follow OS case-insensitivity. It MUST preserve caller argv/override slices including spare backing storage and parent environment/current directory. Existing Run combined-output behavior MUST remain unchanged.

### GIT-009
Capture MUST return Exit 0 and nil Err on success, the actual exit and useful non-nil Err for ordinary nonzero termination, and Exit 2/useful non-nil Err for nil context, empty argv/executable, malformed overrides, nonexistent directories or launch failures without starting a fallback process. Invalid and pre-cancelled calls MUST produce empty streams and no process-created marker. Already cancelled/expired contexts MUST prevent startup with Exit -1 and an Err matching the original context error through errors.Is. Invalid, successful, failing and cancelled calls MUST NOT poison later valid calls. All outcome paths MUST retain caller state and inputs.

### GIT-010
Cancellation or deadline during Capture MUST terminate its entire owned process tree on Linux/macOS/Windows, including children/grandchildren holding output streams, return promptly with Exit -1 and matching context Err, and retain each stream's bytes emitted before termination. Descendants MUST NOT survive to perform delayed writes. Unrelated processes and overlapping Run/Capture calls MUST remain alive and retain independent output/cancellation state, including in a race-instrumented calling executable. Ordinary termination MUST remain distinguishable from context termination. Evals MUST use bounded local helpers without agent/bootstrap/network dependencies.

### GIT-011
Edits MUST inspect the requested local baseline without attempting fetch, push, branch creation or network commands, including partially populated repositories on supported Git versions. It MUST return a useful non-nil error and an empty edit result when objects required to resolve the selected commit or determine its edits are unavailable; it MUST NOT return partial successful edits. Missing unrelated ancestors, trees or blob bodies that are not needed for the requested comparison MUST NOT prevent otherwise available results. Available ordinary and linked SHA-1/SHA-256 repositories MUST retain the existing GIT-003 staged, unstaged, untracked, filename and rename semantics, including built-in Git configuration affecting index/worktree comparisons. Full commit IDs and valid single commit/tag/ancestor expressions MUST remain usable; revision sets MUST be rejected. Successful and rejected calls MUST remain noninteractive, use literal arguments, preserve HEAD, refs, original index bytes, working/ignored files and parent cwd/environment, and clean owned temporary storage. No bootstrap or authenticated agent MAY be required or invoked.

### GIT-012
Clean MUST inspect only locally available repository state without attempting fetch, push, branch creation or network commands. Configured monitor and external content-conversion callbacks MUST NOT run, and no bootstrap or authenticated agent MAY be required or invoked. It MUST retain GIT-003 clean/dirty meaning for staged, unstaged, deleted and untracked files while ignoring ignored files, including native built-in normalization, attributes, excludes and index/worktree configuration on available ordinary and linked SHA-1/SHA-256 repositories. Valid ordinary unborn repositories and nested checkout paths MUST remain usable. Missing objects required to determine cleanliness and invalid roots MUST return false with a useful non-nil error; missing unrelated ancestors, trees or blob bodies not needed by the comparison MUST NOT prevent otherwise available clean or dirty results. Successful and rejected calls MUST be noninteractive, preserve original HEAD, refs, index bytes, configuration, working/ignored files and parent cwd/environment, and clean their owned temporary storage.

## Decisions

[local-repository]
Git operations use argument vectors, not shell interpolation. Edit statuses are A/M/D/R (or another first status character reported by Git); rename Path is the new path and OldPath the old path. Untracked files are A. The diff is relative to the requested commit, not merely the index. Identical entries are deduplicated and results sorted by Path then OldPath then Status. SafePath rejects dangling symlinks and roots that do not exist. Root canonicalization follows symlinks. Base resolution reads only local refs; names are validated with git check-ref-format to prevent revision/options injection. Invalid base/remote names return errors. No temporary branches or network commands are used by inspection.

[command-process]
Exit -1 identifies context termination inside this process API, while CLI layers retain their separately specified 0/1/2/3 meanings. The original context error is exposed for callers to classify timeouts and cancellation without parsing process messages. Launch/configuration errors use Exit 2. Explicit shell invocation remains possible but substitutions and quoting belong to the hook/agent caller, not this adapter. This primitive does not create Git branches or invoke Git by itself. Windows environment keys follow the operating system's case-insensitive semantics. Runtime platform evidence must be reported honestly; cross-compilation cannot establish cancellation behavior on an unexecuted platform.

[race-helper-exit]
Use the Go race runtime's exit-sleep setting only for bounded helper subprocesses. Do not increase the tested process termination bound or remove the live unrelated-process predicate. This is a test harness repair for already implemented behavior, governed through evals/audit/impl/archive so permanent eval changes are reviewable and never smuggled into an implementation commit. Implementation phase requires no product code edits. Keep the original race failure in .fireweed/evidence/go-race-process-checkpoint.log and record the corrected full-run result separately.

[process-capture]
Separate streams are protocol inputs; no inter-stream ordering is promised. Retain Run's combined stream semantics for existing hooks/agents. Both entry points may share a disposable process execution core with independently owned writers. The adapter itself grants no permission to run Git hooks or remote commands: callers remain responsible for their explicit argv and environment. Exit -1 is the existing internal context-termination convention, distinct from CLI exit meanings.

[git-read-locality]
BaseRef chooses an existing exact tracking ref by local ref identity rather than requiring that ref's target commit body. An unavailable target is not permission to fetch or silently substitute a different base. Preserve configured/default remote/branch selection, slash-containing names, symbolic remote defaults and absent-tracking fallback under GIT-002. Existing edit ordering, rename source/destination and filename-byte contracts remain authoritative.

Availability is scoped to the requested operation. Do not validate every reachable commit/blob or decode unrelated content as a precondition. Prove the unavailable-object transport observer with real local Git controls, including a denied protocol where a fetch child may still be attempted. Clear controls before API calls and snapshot all state after fixture construction. Native Git output on available fixtures supplies the comparison result; a reference command that fails is not a positive control.

The implementation retains a cancellation watcher for the complete public call, including inherited streams after the direct command has exited. On macOS, native creation/lifetime identities and stable original-parent identities locate reparented owned descendants; cancellation freezes live parents before child discovery and checks identities before signals. On Linux, each call uses a separate statically linked helper with PR_SET_CHILD_SUBREAPER, so adopted descendants remain scoped to that call across parent exits, groups and sessions. Only this helper becomes a subreaper. It reaps its own children, forwards exact streams and reports the requested executable's outcome over private close-on-exec descriptors. The target retains its original argv, environment and working directory. Combined Run streams share one target pipe; Capture keeps two. The parent loads an architecture-specific, source-generated compressed helper through an anonymous memfd. No calling-program initializer, shell, Go compiler, bootstrap, external helper installation or network is involved at runtime. Helper source and reproducible generation instructions live in the same disposable implementation zone; tracked images support all Go Linux architectures. Ordinary uncancelled completion follows root-exit and stream-drain semantics. Windows retains its existing suspended-start job ownership.
