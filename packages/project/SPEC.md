# project

## Specs

### PRJ-001
Load MUST discover the canonical Git root from a nested directory, parse fireweed.yaml using the running embedded version, resolve the local base ref, and discover SPEC.md only in module directories matching configured modules globs. It MUST retain resolved module defaults, explicit empty overrides, dependencies, hooks, specs, Decisions and original documents. Modules MUST be sorted by name then directory. It MUST NOT follow directory symlinks or read files through escaping symlinks, run hooks/agents, use the network or mutate repository files/refs. Missing/invalid configuration or invalid configured globs MUST return an error mentioning C01; a nonrepository MUST return an error.

### PRJ-002
Load MUST continue past malformed module/change documents and retain path-attributed diagnostics: C02 warning for SPEC.md outside module globs, C03 error for invalid module metadata, C04 error for invalid Specs grammar, and C05 error for malformed changes or unknown target modules, except that undeclared live handle references MUST produce C09 error diagnostics. Queued handle references anywhere in the change, including human sections and metadata, MUST be local to that change; a declaration in a different change MUST NOT satisfy them. Archive human sections MUST preserve literal handle examples without treating them as live references; archive edit sections and metadata MUST still validate their live references. It MUST ignore .git and .fireweed trees during module discovery. Queue and archive MUST include immediate Markdown files only, parsed with each target's prefix, retaining lifecycle/provenance/author sections; each list MUST sort by numeric filename then slug. Duplicate slugs across either list MUST produce C05. Symlink escapes MUST produce an error diagnostic without reading their contents.

### PRJ-003
Check MUST diagnose duplicate module names or prefixes with C03 and overlapping module directory ownership with C06, including future paths. Dependencies MUST name existing modules, exclude self and have no cycles; violations MUST produce C06. Valid acyclic graphs, including shared transitive dependencies, MUST pass this graph check.

### PRJ-004
Check MUST reject invalid module-relative zone patterns with C03 and eval/disposable intersections with C06, including intersections at nonexistent paths. Nonintersecting zones MUST pass; interface/preserve/append-only overlap with disposable MUST remain permitted under strict precedence. It MUST NOT require files to exist or execute hooks.

### PRJ-005
Check MUST require a nonblank resolved eval hook (C07 error). Modules with disposable globs MUST have a nonblank boundaries hook or a nonblank boundaries_opt_out reason (C07 error otherwise). Every explicit opt-out MUST emit a D04 warning containing its reason; a module without disposable globs and without boundaries MUST emit a D04 warning. Boundary opt-outs MUST NOT waive the eval hook requirement.

### PRJ-006
Check MUST reject any current spec ID listed as Removed in the archive with C08, preserving removed-ID reservations. It MUST include all Load diagnostics and return a non-null deterministically sorted diagnostic list by path, code, severity and message, with nonempty corrective messages and path attribution for module/change issues. A valid snapshot with no warnings MUST return an empty list. Check MUST NOT mutate the supplied snapshot.

### PRJ-007
ApplyChange MUST replace Modified specs in their existing positions, remove Removed specs, and append Added specs in declared order, retaining complete bodies and tags. It MUST retain local Added handles for preview without allocating IDs. It MUST reject a mismatched target module, missing Modified/Removed targets, repeated edit IDs, existing-ID additions, wrong-prefix IDs, malformed normative edits and invalid Removed bodies with an error rather than returning a partial result. It MUST update the document's Specs section to reflect the resulting ordered items while retaining the module preamble and unrelated sections.

### PRJ-008
ApplyChange MUST apply only allowed set fields: depends_on, interface, evals, disposable, preserve, append_only, boundaries_opt_out and named eval/boundaries/setup hook overrides. Explicit empty lists/strings MUST replace resolved values, omitted fields MUST retain them, and partial hooks MUST retain other resolved hooks. Identity edits, unknown fields and wrong field types MUST fail. The returned module's fields and document metadata MUST agree, retaining original valid metadata and unrelated document sections; name, prefix and directory MUST remain unchanged. Projection MUST NOT read a configuration file or re-inherit project defaults over explicit values.

### PRJ-009
Project MUST apply changes in numeric Number then Slug order across their target modules, independent of input slice order. A nonempty before selector MUST return the state after preceding changes only; empty before MUST apply the entire queue. Same-number changes MUST follow slug order. Unknown/ambiguous selectors, unknown target modules and invalid application MUST return errors. Current archive entries MUST NOT be replayed as pending changes. Project MUST preserve unrelated snapshot data, and neither successful nor failed projection/application MAY mutate inputs or return mutable aliases of any input module, document, configuration, change, archive, metadata map or slice. These APIs MUST NOT read/write files, run hooks/agents/Git or use networking.

### PRJ-010
BaseHashes MUST compute a fresh non-null map containing exactly the Modified and Removed IDs of the selected queued change, hashing the target specs as projected immediately before that change. Hashes MUST use the public normalized eight-character SHA-256 item contract, including tags; existing bases MUST be replaced in the returned map without changing input state. Added-only or maintenance changes MUST return an empty map. Missing/ambiguous change, missing target module or missing edited spec MUST return an error. The function MUST remain pure and independent of files and Git, and changing a returned map MUST NOT affect inputs or later calls.

### PRJ-011
CheckQueue MUST process changes in numeric Number then Slug order against preceding structurally valid intent. Every Modified and Removed ID MUST exist immediately before its change and have a matching normalized public SpecHash in bases; missing targets, missing hashes and stale hashes MUST emit C10 error diagnostics at that change's path. Tag changes MUST affect comparison while normalized line endings/trailing whitespace MUST NOT cause false staleness. Stale or missing hashes MUST NOT stop projecting structurally valid intent for later base checks.

### PRJ-012
CheckQueue MUST apply each structurally valid change's set values before validating graph, zones, hook requirements and archive reservations with the public static contract. Newly introduced C03, C06, C07, C08 and D04 diagnostics MUST be attributed to the introducing change path and retain corrective detail, including opt-out reasons. It MUST NOT repeat unchanged preexisting current/static/discovery diagnostics, and a valid later change that removes an introduced problem MUST pass. Every intermediate projected state MUST be checked, even when a later change repairs it; future-path intersections MUST be enforced without requiring files to exist.

### PRJ-013
Unknown target modules and invalid typed changes/applications MUST emit C05 errors; undeclared or cross-change-only handles anywhere in a change MUST emit C09 errors. Structurally invalid applications MUST be skipped while later independent changes are still checked. Real-ID Added items without run and phase MUST be rejected as author-chosen IDs with C05; a removed archive ID MUST be rejected with C08 even when the change also lacks assigned state. Assigned-state additions with unused valid IDs and local author handles MUST remain accepted. fixes IDs MUST exist before the change and remain present after it; already_satisfied IDs MUST exist in the resulting module. Missing or removed references MUST emit C05.

### PRJ-014
CheckQueue MUST return a fresh non-null diagnostic slice sorted by path, code, severity and message, with nonempty corrective messages and error/warning severity. It MUST NOT modify or return mutable aliases of input snapshots, modules, changes, archives, configuration, diagnostics or nested documents/maps/slices, on valid or invalid input. It MUST NOT read/write files, execute hooks/agents/Git or use networking. An empty queue MUST return an empty slice regardless of unrelated input discovery/static diagnostics. A valid queue MUST return an empty slice.

### PRJ-015
Allocate MUST select exactly one queued change by slug and resolve exactly one existing target module. For an unstarted change it MUST assign each local Added handle in declaration order, using the target prefix and consecutive numbers above the greatest numeric ID reserved by current target-module specs, every target-module archive Added/Modified/Removed item, and real Added IDs in other target-module queued changes with both run and phase. ID formatting MUST use at least three decimal digits and support existing larger decimal widths without overflow. Other modules, author prose, bases/reference-only mentions and other unstarted handles MUST NOT reserve numbers. Author-chosen real Added IDs, partial run/phase state and applied queued state MUST error. A valid already started change with real Added IDs MUST retain those IDs/run/phase and return an empty mapping; a started change still containing handles MUST error rather than allocate on resume.

### PRJ-016
Allocate MUST rewrite every occurrence of each declared handle in canonical change metadata, preamble and every body section, including Added/Modified text, Interface, Decisions, Notes and fenced examples. Overlapping handle names MUST NOT corrupt one another. already_satisfied and nested set hook references MUST become the same assigned IDs as their Added declarations. Returned typed fields and Document MUST agree; unrelated author text, section order, tags, real IDs, lifecycle state and metadata MUST retain their semantic values under the public Markdown normalization contract. Typed change fields MUST override stale retained metadata/edit sections. Returned Path, Slug and Number MUST retain the selected typed identity even when filename numbering differs from Number. On new allocation and valid resume, Added/Modified/Removed sections with nil or empty typed item lists and absent retained headings MUST remain absent. Existing empty edit headings MUST retain their names and positions. Nonempty typed edit lists MUST create or update their corresponding sections without introducing unrelated empty edit sections. All other retained heading presence and relative order MUST remain unchanged, and fenced heading text MUST NOT count as an existing edit section.

### PRJ-017
Allocate MUST return errors for missing/ambiguous selectors or targets, invalid selected typed change grammar and undeclared/cross-only handle references, without returning a partial change or allocation mapping. It MUST validate only the selected change's grammar, without replaying or requiring validity of excluded queue entries. Successful empty mappings MUST be fresh non-null maps. Successful results and mappings MUST have no mutable aliases to the supplied snapshot, modules, changes, archive, configuration or nested documents/maps/slices; neither success nor error MAY mutate inputs. Repeated calls with the same input MUST be deterministic. Allocate MUST NOT read/write files, execute hooks/agents/Git or use networking.

### PRJ-018
Finalize MUST apply Added/Modified/Removed specs and all allowed set values through the existing public projection contract, retaining item order, tags, module identity, preamble and unrelated sections. Its result MUST be a valid current module with real IDs only, with resolved fields, Specs and metadata agreeing under public Markdown normalization. It MUST reject invalid applications and remaining local handles in current or resulting specs, returning a zero Module on error. The change MUST have a nonempty valid slug consistent with its filename; differing numeric filename/typed Number values MUST remain permitted. Finalize MUST NOT assign IDs, change run/phase, write the change, or incorporate the change's Motivation, Interface, Notes, Audit, Questions or Provenance into the module.

### PRJ-019
Finalize MUST start from the module's typed Decisions, overriding a stale retained Decisions body. For each nonempty line in the change's Removed decisions section, it MUST trim surrounding whitespace and one optional leading blockquote marker and remove every exact occurrence of that quoted text from existing Decisions; unmatched quotes MUST be harmless, and unrelated text MUST remain. It MUST then append the change's nonempty Decisions body, preceded by a bracketed change slug on its own line and separated from existing nonempty Decisions by one blank line. It MUST preserve multiline/fenced decision content and existing slug tags under public Markdown normalization. No new Decisions section MUST be invented when none exists and neither removal nor addition requests one; an explicit removal request MUST retain a Decisions section even if its resulting body is empty. The typed Decisions field and document body MUST agree.

### PRJ-020
Finalize MUST be deterministic and pure on successful and failed inputs, without filesystem/network I/O or execution of Git, hooks or agents. It MUST NOT mutate or return mutable aliases to the supplied module, change, retained documents, metadata maps or slices. Separate calls and input values MUST remain unchanged immediately when a returned result is mutated, including valid maintenance changes with no spec edits. Errors MUST return no partial module. ApplyChange MUST remain a preview retaining existing Decisions without performing final decision additions/removals.

### PRJ-021
ResolvePlaybook MUST recognize exactly the five names in public assets.Playbooks and resolve the canonical Git checkout from start, including nested directories and linked worktrees. Without the selected .fireweed/playbooks/<name>.md override it MUST return the exact public embedded Text and Hash, EmbeddedHash equal to that embedded Hash, Name equal to the requested name, BasedOn empty, Overridden false and Stale false. With a readable regular selected override it MUST return every exact byte of that file as Text, SHA-256 of those exact bytes as lowercase full Hash, the unchanged embedded hash as EmbeddedHash, and Overridden true, including empty files and CRLF text. Only the selected override may affect the result; unrelated overrides and project configuration MUST NOT be read. Unknown or path-like names MUST error with valid-name guidance before repository discovery or override reads; a known name outside any Git repository MUST error with corrective repository guidance. Every error MUST return a zero Playbook.

### PRJ-022
For an override, ResolvePlaybook MUST extract BasedOn only from a string-valued based_on key in valid public Markdown frontmatter. Stale MUST be false exactly when that string equals the selected current embedded hash, and true for missing, wrong, differently cased or non-string hashes and malformed frontmatter. Staleness MUST NOT replace or reject readable override text: Text and its exact-byte Hash remain the override's values, even for invalid frontmatter, absent based_on or an empty file. The full file including frontmatter MUST remain in Text and Hash. Embedded-only resolution MUST remain non-stale independently of other overrides.

### PRJ-023
ResolvePlaybook MUST check selected override containment using the public Git SafePath contract before opening its contents, including when a read error would otherwise be ignored. Missing selected overrides MAY fall back to embedded text only when the missing path remains contained. Unreadable files, directories and escaping or dangling symlinks, including missing descendants of escaping directory symlinks, MUST return a corrective error mentioning D05 and the selected repository-relative override path, never silently fall back or read outside contents. Contained regular-file symlink targets MAY be used. Resolution MUST be deterministic, noninteractive and read-only on success, stale overrides and all errors: preserve tracked/untracked/ignored/outside files, index bytes, HEAD/branches/claim/other refs, parent cwd/environment and temporary storage; never run hooks/agents/bootstrap/network commands or mutate project configuration. Calls and returned values MUST remain independent without mutable aliases or input mutation.

### PRJ-024
LoadAt MUST discover the canonical calling checkout from start, including nested directories and linked worktrees, and resolve one explicit nonblank local revision to a full commit before reading its tree. It MUST accept full commit IDs, local branches, annotated/lightweight tags and commit expressions supported by installed Git, in SHA-1 and SHA-256 repositories. An absent/invalid/option-like revision, blob/tree object, unborn HEAD, unavailable repository or Git resolution/enumeration failure MUST return a corrective C01 error and zero Snapshot. All subsequent tree/blob reads MUST be pinned to that resolved commit or its object IDs even if the input ref moves. No current file, index, HEAD or newer commit may replace selected metadata.

### PRJ-025
LoadAt MUST parse the selected commit's fireweed.yaml with public ParseConfig and the embedded binary version, validate configured glob syntax, resolve BaseRef from that config and locally known refs, and return canonical Root. It MUST discover module SPEC.md paths from the selected tree with the same configured-glob, ignored .git/.fireweed subtree, metadata/spec grammar, resolved-default/explicit-empty, retained document/Decisions and name/directory sorting contract as Load. It MUST parse immediate Markdown queue/archive files from that tree, using target prefixes, the existing live/archive handle rules and numeric/slug order; preserve all author/lifecycle/provenance sections; and diagnose duplicate slugs across both lists. It MUST continue past malformed selected documents with the same C02/C03/C04/C05/C09 severity, path and corrective categories as Load, while invalid/missing/unreadable configuration or invalid configured globs is fatal C01. Empty Modules, Changes, Archive and Diagnostics MUST be non-null on success, with diagnostics sorted by path/code/severity/message. Graph/zone/hook/static and queue checks remain the existing public validators' responsibility.

### PRJ-026
Metadata file links MUST resolve only within the selected Git tree. Relative symlink targets and absolute targets lexically within the canonical calling root MUST resolve to selected-tree regular blobs, preserving the target bytes and link-relative path semantics without consulting current worktree link targets. Chained contained links and executable regular blobs MUST work; escaping targets, dangling links, loops, NUL/backslash-invalid paths, directories or gitlinks in place of selected metadata MUST be rejected with the corresponding configuration/module/change category, never read outside/current content or silently substitute another source. Module discovery MUST NOT traverse directory symlinks, gitlinks or nested .git/.fireweed subtrees. Out-of-glob SPEC.md contents and unrelated blobs MUST NOT be read. Explicit queue/archive directory links that resolve within the selected tree MUST expose immediate Markdown entries at their logical changes/ or changes/archive/ paths. Directory links in selected metadata targets MUST use the same contained virtual-tree rules; no filesystem traversal is permitted.

### PRJ-027
LoadAt MUST read only necessary local Git metadata and selected config/module/immediate queue/archive blobs and their committed link targets; it MUST NOT read current working-file contents or unrelated historical code/private/playbook/recipe blobs, including when an eventual error would be ignored. Dirty, deleted, untracked, staged, ignored, symlinked or unreadable current metadata MUST NOT affect the selected snapshot. Successful snapshots and all nested data MUST be independent of inputs and existing repeated results, including empty append backing storage; failures MUST return no partial Snapshot. Every call MUST remain local/noninteractive, preserve files/index/HEAD/branches/claim/other refs/common Git/user/outside data and parent cwd/environment/temp storage, and MUST NOT create a temporary checkout/worktree/export, run native Git or fireweed hooks, agents, bootstrap or network commands, or commit/stage/reset/fetch/push/create branches. Literal Git arguments and hook suppression MUST keep configuration strings and unusual filenames inert. Existing Load behavior MUST remain unchanged.

## Decisions

[discovery-validation]
This slice validates the current static graph. Queued projection, set application, hash bases and late ID assignment are separate changes. Discovery scans all repository directories except .git and .fireweed to report out-of-glob specs; WalkDir does not traverse directory symlinks. Symlink file paths are checked by gitstore.SafePath before reads. Configured globs include module discovery, defaults, protected and worker_writable patterns. Module metadata is validated separately from its Specs body so malformed normative content receives C04. Unknown archived target modules are diagnosed C05, rather than silently dropping history. Hook strings remain opaque and are never evaluated by static checks. Module path attribution is <dir>/SPEC.md; queue/archive attribution is its repository-relative path. A root module directory is represented by '.'.

Variable-width numeric-order fixtures use at least four digits, as required by the retained document contract. Original documents retain all valid known metadata and arbitrary human sections; unknown metadata is rejected by contracts. Adjacent stars inside a segment are ordinary wildcards; invalid-pattern tests use malformed classes, absolute/traversal paths and repeated separators. The superseded first cycle was fully reverted after these fixture mistakes surfaced (author decision D008).

[queued-projection]
Projection is an intent preview: it does not enforce existing bases or allocate real IDs. Later queue validation reports missing/stale bases, invalid graph/zones after set, and archive reservations; lifecycle allocation rewrites handles only at start. ApplyChange uses the typed Module and Change fields as authoritative, updating retained documents accordingly. Local handles may appear in Added and references, with the same uniqueness/locality rules as the public change parser; file-backed current module specs and Modified/Removed targets use real IDs. Projected intermediate modules may contain placeholders from preceding changes. Field/type and spec-edit validation is required even for callers constructing typed values directly. An empty module Document is synthesized from typed fields; valid original documents retain preamble and human sections. Project keeps the original pending changes/archive lists and diagnostics as independent copies, preserving their original ordering; only the order of application is sorted. Diagnostics, canonical module ordering and graph validation remain separate existing Check responsibilities. Decisions application/removal will be a separately specified part of archival application; this preview retains existing module Decisions.

ApplyChange errors return the zero Module, never a partial result. Existing-ID addition collisions mean real allocated IDs; handle placeholders are local declarations, so two queued changes may each declare new:local and their preview retains both items without treating that shared spelling as an allocated-ID collision. References in each change must still be declared locally. A preview document can therefore contain repeated placeholder headings from different changes, and is never written as a current SPEC.md until start has allocated real IDs. Invalid excluded target/tail applications are not executed or validated by Project(before); ambiguity of the selector itself is still an error. Base hashes follow typed spec fields, including normalized whitespace, rather than stale retained document text.

The public diagnostic conversion keeps the established non-null slice convention; diagnostic contents and ordering are preserved. Projection otherwise preserves nil versus explicit empty configuration/module lists through independent copies.

[queue-validation]
CheckQueue complements current-state Check and never repeats its input diagnostics. It checks transitions incrementally: newly introduced static diagnostics are compared with the previous projected state's diagnostic signatures; each new problem is attributed to its change. Stale-base errors do not erase the author's intent. Failed structural application skips that change's intent and continues with other queued changes. Numeric/slug application ordering follows typed fields. Assigned state means both nonempty run and phase; normal workflow/history enforcement proves ownership later.  Decisions application, late allocation and all-occurrence rewriting remain separate upcoming changes.

Archived non-edit human sections are historical prose, not live handle bindings. Validate archive metadata and Added/Modified/Removed with public change grammar using a validation-only view whose other bodies are neutral, then retain the original complete parsed document. Queued documents are validated in full. This permits worker Decisions to explain handle examples after allocation without modifying or losing immutable archive history. Author decision D010 records the live regression.

[late-allocation]
The highest reserved number plus one implements next-free allocation without reusing historical gaps. Use arbitrary-size decimal arithmetic rather than wrapping or truncating large IDs accepted by the public grammar. Queued reservations require assigned state; invalid unstarted real-ID additions do not burn the namespace. Prefix uniqueness and overall queue/application checks remain the existing validators' responsibility. Allocation validates the selected change with canonical typed fields and returns a public parser-normalized representation while preserving its typed identity. Run/phase assignment, ownership, atomic file writes and eligibility belong to workflow. Resume keeps assigned values and returns no new bindings. An empty slug is not an all-queue selector here.

[final-application]
Removed-decision quoting follows the pinned reference's line-wise exact-text convention, including optional Markdown blockquote markers and harmless unmatched quotes. Public rendering/parsing defines normalization of remaining whitespace and human content. Each change appends one slug-tagged body, preserving multiline choices and fenced examples as text. Finalize is not an idempotent transaction: the workflow validates, writes and archives once, and handles rollback separately. Existing ApplyChange remains the placeholder-capable preview and therefore does not perform final Decisions edits. Current CON-016 permits locally declared Added handles in already_satisfied before allocation; fixes and bases remain real-ID-only. Allocation must rewrite those handles before this final transform can produce a current SPEC.md.

[project-playbooks]
This API binds explicitly to an existing Git checkout without reading fireweed.yaml. The CLI retains its existing embedded-only behavior outside a project and will opt into this resolver when project binding is appropriate. Hashes cover the complete exact override file, including frontmatter, because that is the text supplied to workers and recorded in provenance. based_on inspection uses the public Markdown parser; malformed metadata is advisory staleness, while failed or unsafe reads are errors. Empty override files remain author-owned instructions and produce a stale flag. SafePath defines containment; inside links remain permitted without weakening worker zone rules.

The reference Project.Playbook reads complete override bytes and hashes them, and Doctor compares based_on with its embedded hash (internal/fireweed/playbooks.go and doctor.go). This fresh API exposes those two observations together without running doctor or hooks. Static input validation and command rendering remain callers' responsibilities.

[baseline-snapshot]
The caller supplies the approved commit (normally Claim.Base). Resolve it once; metadata body reads use immutable blob IDs, not mutable ref:path expressions. Snapshot has no new provenance field: the caller already retains the full claim baseline. BaseRef is still the selected config's local ref name, resolved through the established defaults; it is not the selected source commit itself. No network refresh occurs.

This is selected-tree discovery, not a scratch checkout. Symlinks are interpreted as committed bytes in a virtual slash-separated tree with lexical containment; absolute links are rooted only in the canonical calling checkout, without consulting current filesystem aliases. File links can target contained committed metadata elsewhere, but discovery does not invent module trees through directory aliases. Gitlinks do not import foreign repository contents. Physical permissions on current metadata cannot restrict an available committed blob. Existing malformed-document diagnostic categories and archive-human-prose treatment remain shared with Load.

This API does not trust or reload a worker's current config/SPEC, does not validate claim ownership, replace a selected change with Claim.State, collect edits, construct a worker prompt or advance a phase. Workflow will compose those responsibilities. Static Check/CheckQueue remain explicit, allowing callers to inspect a diagnosed baseline while repairing source state.

[allocation-sections]
Known edit headings are synthesized only when their typed lists have items. A retained edit heading remains present and in place even when its authoritative typed list is empty; stale retained items are cleared. A missing heading with nonempty typed items must still be synthesized. Preserve arbitrary human sections and their relative order, including empty sections and fenced examples. Both fresh allocation and valid started resume use the same canonical view. This repairs document preservation rather than weakening approval content checks or adding lifecycle behavior.
