# workflow

## Specs

### FLOW-001
CheckState MUST parse approved and current text with the public change grammar, using the supplied module's ID prefix and the supplied change path. An invalid approved document, an approved target different from the supplied module name, a missing run, or an approved phase outside evals/audit/impl MUST return a P02 error at that path with corrective claim guidance. Once approval is valid, invalid current text MUST return P2-01 at that path with corrective worker-edit guidance. Invalid state MUST NOT be accepted as an unchanged change. A valid unchanged started change, including maintenance and regenerate changes, MUST return an empty non-null diagnostic slice.

### FLOW-002
CheckState MUST reject semantic changes to every approved metadata field except blocked with P2-01, including module, nested set/hook/zone values, bases, fixes, already_satisfied, regenerate, run and phase, and adding or removing metadata keys. Valid blocked reasons MAY be added, replaced or removed. For an approved evals or impl phase it MUST permit adding, changing, moving or removing Decisions, Questions and Notes sections; for an approved audit phase it MUST permit only Audit and Questions sections. Every other parsed section, its body and relative order, and the parsed preamble MUST remain unchanged. Protected edits MUST yield P2-01, including Motivation, Interface, Added/Modified/Removed, Removed decisions, Rejected alternatives, Provenance, unknown sections and changes hidden after duplicate or fenced headings. Permissions MUST derive from the approved phase even when current metadata attempts to switch phase. Metadata ordering/quoting and line-ending changes with the same public parsed values MUST NOT be rejected. Exact case-sensitive section names and public fenced-Markdown parsing MUST determine permissions rather than substring replacement.

### FLOW-003
CheckState MUST return fresh non-null diagnostics sorted deterministically by Path, Code, Severity and Message, with severity error, the supplied path and nonempty corrective messages for every rejection. Metadata and protected-body violations in the same valid current document MUST both remain visible; invalid approved or current grammar MUST stop that comparison rather than inventing partial acceptance. Results, including writable empty results, MUST remain independent across repeated calls, and supplied module fields/maps/slices and input strings MUST remain unchanged. It MUST work from supplied text outside any repository, remain noninteractive and MUST NOT create or edit files/refs, execute Git, hooks, agents, the bootstrap or network commands on successful or rejected calls.

### FLOW-004
CheckEdits MUST use the supplied approved module's projected zones in preference to the snapshot's stale selected-module zones, and repository-relative ownership from every other snapshot module. It MUST reject protected paths, every basename SPEC.md, other modules' paths and every changes/ path except a modification of the exact current change with P2-01. worker_writable MUST permit only otherwise unowned paths and MUST NOT override protected, spec, other-module or other-change restrictions. Exact current-change modifications MUST be allowed for all worker phases; CheckState separately enforces its content. Paths outside modules and worker_writable MUST be rejected with P2-01. Prefix-similar module/change paths MUST NOT be mistaken for owned or current paths.

### FLOW-005
For an approved evals phase, CheckEdits MUST permit target evals, other module files such as manifests, permitted worker_writable paths, and new disposable files only. Interface edits MUST require a nonempty exact Interface section in the approved change, otherwise returning P1-01. Preserved and append-only additions or edits, and modification, deletion, type change or rename of disposable files MUST return P1-01. Both source and destination of every rename MUST be checked against their own zones and owners, so moving protected, other-module, eval, interface, preserved, append-only or existing disposable files cannot evade their phase restrictions. A copy's source is unchanged: it MUST have a valid path but MUST NOT be treated as an edit; its destination MUST be checked as a new addition.

### FLOW-006
For an approved impl phase, CheckEdits MUST permit target disposable, preserved and other module files and permitted worker_writable paths, but reject every target eval or interface addition, modification, deletion, type change or rename with P2-01. For audit, it MUST reject every edit except modification of the exact current change with P2-01. Independently of phase and zone precedence, every modified, deleted, type-changed or renamed endpoint matching any owning module's append_only glob MUST return H03, including overlaps with stricter zones and edits to other modules. Append-only destinations of additions or copies MAY be accepted in impl when other restrictions permit; evals MUST reject them with P1-01. All independent H03 and phase/ownership violations MUST remain visible at their own paths.

### FLOW-007
CheckEdits MUST reject a missing run, mismatched approved target or approved phase outside evals/audit/impl with P02 at the current change path and corrective guidance, stopping file-policy comparison. It MUST reject malformed edits with P2-01: only A/M/D/T/R/C statuses are accepted; all paths MUST be canonical slash-separated repository-relative file paths without empty, dot, parent, absolute, backslash or NUL components; R/C MUST have a distinct valid OldPath and other statuses MUST NOT have OldPath. It MUST return fresh non-null diagnostics sorted by Path, Code, Severity and Message, deduplicating identical diagnostics, with severity error and nonempty corrective messages. Inputs, nested maps/slices and earlier results MUST remain unchanged, including immediately after result mutation and on rejected calls. Successful and rejected calls MUST remain noninteractive outside a repository and MUST NOT read or mutate files/refs, run Git, hooks, agents, the bootstrap or network commands, or change parent cwd/environment.

### FLOW-008
CreateClaim MUST store a JSON blob at refs/fireweed/claims/<slug> using an atomic create-only Git ref update, with the canonical current worktree root, exact slug/run/state and a full resolved local commit ID for Base. It MUST return that stored Claim and its full blob Object token, without committing or moving HEAD. Only nonempty slugs matching lowercase letters/digits followed by lowercase letters/digits/hyphens and a nonblank run are valid; invalid slugs, missing runs, unavailable repositories and unresolvable commit bases MUST fail with P02 and corrective guidance and create no claim. Empty State MUST be allowed as an initial reservation. Competing creates for the same slug, including from linked worktrees, MUST have exactly one winner; a conflict MUST preserve the winner and report its ownership/release guidance. Different slugs MUST remain independent.

### FLOW-009
UpdateClaim MUST require the exact current Claim, including its Object token, held by the calling canonical worktree; it MUST preserve Worktree, Change and Run, replace State exactly, resolve the new Base to a full local commit ID and atomically replace only the expected blob ref. A stale, modified or foreign-worktree previous Claim MUST fail with P02 and corrective guidance without overwriting current ownership. ReleaseClaim MUST atomically delete only the named ref matching the supplied full Object token, and MUST reject missing/stale/invalid tokens or missing claims with P02 and corrective guidance. Explicit release MAY be performed from another linked worktree; it MUST NOT delete a replacement claim. Updates and releases racing on one token MUST NOT both succeed, except that a genuinely unchanged update MAY retain the same content-addressed token.

### FLOW-010
LoadClaim MUST read the exact shared claim ref, return its complete independent stored fields and full Object token, and reject missing refs, non-blob objects, malformed JSON, trailing JSON values, missing or incorrectly typed required fields, invalid slug/run/worktree/base values and stored Change differing from the requested slug with P02 and corrective guidance. Worktree MUST be an absolute clean path, but its directory MAY no longer exist so stale claims remain inspectable. Claims MUST list every shared claim in ascending Change order, excluding unrelated refs; an empty inventory MUST be non-null. It MUST reject malformed claim refs or payloads atomically rather than silently skipping them or returning a partial inventory. Failed Claim-returning calls MUST return a zero Claim, and separate returned inventories/claims MUST remain independent.

### FLOW-011
Every claim operation MUST remain local and noninteractive, use literal Git arguments, and MUST NOT run fireweed hooks, native Git ref-transaction hooks, agents, the bootstrap or network commands. Successes and rejections MUST preserve HEAD, branches, the caller's index, working files, ignored/user files, other refs, input Claim values, parent cwd and environment; only the selected claim ref and necessary Git object storage MAY change. Temporary owned storage MUST be cleaned on success and failure, including duplicate-create and stale-update failures. Reads and failed precondition checks MUST NOT change refs. Claims MUST work across linked worktrees and in SHA-1 and SHA-256 repositories supported by installed Git, without a hard-coded object-ID width. Claim operations MUST NOT fetch, push, create branches or require author identity, authenticated agents or network access.

### FLOW-012
CheckWorktree MUST discover the canonical checkout from snapshot.Root, require the exact current stored Claim including Object and fields, require that claim's owner to be this checkout, and require HEAD to equal Claim.Base. It MUST validate Claim.State as an unchanged valid started document through CheckState and public change grammar, with parsed Module, Run and Slug agreeing with the supplied module and Claim. changePath MUST name that queued change directly under changes/, never an archive or escaping/invalid path. Unavailable repositories, missing/stale/tampered/foreign claims, moved HEAD or invalid approved state/identity/path MUST return a corrective P02 at changePath, empty non-null Edits, and stop before current-file comparison or edit collection. Linked worktrees and SHA-1/SHA-256 claim records MUST be supported without changing HEAD or ownership.

### FLOW-013
After valid preconditions, CheckWorktree MUST read the exact current change only after checking its path's containment with the public SafePath contract. Missing, unreadable, directory or escaping/dangling-symlink current changes MUST produce corrective P2-01 at changePath; escaping file contents MUST NOT be read even when read errors would be ignored. Safe in-repository links MAY be read, but their actual type-change edits MUST still obey CheckEdits. Valid current text MUST be compared with Claim.State through CheckState, using the approved phase rather than worker-modified metadata. Invalid current grammar, immutable metadata or protected body edits MUST retain those exact public state diagnostics. Allowed worker prose and blocked edits MUST remain permitted by this guard; blocking/Questions policy is separate.

### FLOW-014
With valid preconditions, CheckWorktree MUST collect the public Git Edits since the exact Claim.Base, including staged, unstaged and untracked files and preserving rename source/destination records. Collection failures MUST return corrective P02 at changePath. It MUST check containment of every edit destination and every rename/copy source, recording corrective P2-01 at each unsafe endpoint, including nonexisting descendants of escaping directory symlinks. It MUST compose CheckEdits using the supplied approved projected target and validated snapshot, retaining independent state, safety and phase/ownership/append-only violations instead of accepting edits after one check fails. Normal permitted changes MUST pass; protected/global/spec/foreign/other-change edits, impl eval/interface renames and evals existing disposable edits MUST fail through the established public policy. No coverage, boundary hook or agent MUST run in this operation.

### FLOW-015
CheckWorktree MUST return fresh non-null Edits and Diagnostics with diagnostics deduplicated and sorted by Path, Code, Severity and Message. Errors MUST have severity error, their specified path and nonempty corrective guidance. Repeated results, including empty results, and input snapshots/modules/claims/maps/slices MUST remain independent and unchanged immediately after result mutation, on successes and rejections. The operation MUST remain local and noninteractive, preserve HEAD, branches, claim/other refs, index bytes, tracked/untracked/ignored/user files, private outside files and parent cwd/environment, and MUST NOT commit, reset, stage, fetch, push, create branches, execute hooks/agents/bootstrap/network commands or leave owned temporary storage. It MAY perform necessary local read-only Git/filesystem inspection. Supplied snapshots' hook/agent strings MUST NOT be executed even on success or failure.

### FLOW-016
BuildContext MUST select exactly one queued change by its exact Slug from the supplied approved snapshot, reject missing/ambiguous selectors, missing target modules, invalid queued paths or phases outside empty/evals/audit/impl with corrective C05, and return that independent Change. The queued path MUST be directly under changes/ and have the selected slug under the public change filename grammar. It MUST obtain the target Module by projecting all preceding queued changes through public Project and applying the selected change through public ApplyChange, including current specs, metadata, zones and Decisions behavior of those APIs. Later changes MUST NOT affect it. Dependencies MUST contain only that projected target's direct dependencies, in declared order, using modules from the preceding projection; missing dependencies MUST fail C05. Empty Dependencies MUST be non-null. Selection/phase/path/projection errors MUST stop before repository/file access. The caller supplies an approved snapshot; this operation does not reload worker-modified config or module metadata.

### FLOW-017
BuildContext MUST discover the canonical repository from snapshot.Root and return its canonical GitCommonDir, supporting nested roots and linked checkouts. It MUST return exact current queued ChangeText, exact current target SPEC.md as SpecText and exact SYSTEM.md as System, preserving frontmatter, CRLF, empty contents and missing final newlines. A missing SYSTEM.md MUST produce empty System; other system/spec/current-change read failures MUST fail C01 with a corrective path-attributed error. A missing current change MAY use only the exact State from a valid stored claim owned by this canonical checkout whose Change, Run, parsed target and phase match the selected started change; otherwise it MUST fail C01. Unsafe paths MUST fail before content opens and MUST NOT fall back through a claim. It MUST select author-change for an empty phase, otherwise the selected phase, with regenerate taking precedence when Regenerate is true; public ResolvePlaybook MUST provide exact Playbook and PlaybookHash, including overrides, empty text and stale/malformed metadata without new warnings. Resolver errors MUST retain their public corrective details.

### FLOW-018
BuildContext MUST enumerate current tracked and untracked nonignored repository files through local Git, deduplicate and sort Files by repository-relative slash Path and preserve exact content bytes. Tracked ignored files MUST remain eligible; untracked ignored files MUST be excluded. In every phase it MUST include only the target's eval and interface files; outside audit it MUST additionally include target preserved/append-only files and direct dependency interface files. Selection MUST use the projected target zones, preceding projected dependency zones and public ZoneFor precedence with configured protected paths. Audit MUST exclude preserved/append-only and dependency interface contents. Disposable, other/manifest, unrelated module, transitive-only dependency, worker_writable-only, protected and SPEC.md files MUST NOT appear in Files or have their contents read by this enumeration. Missing tracked selected files, unreadable selected files, directories and unsafe/dangling selected paths MUST fail C01 rather than being silently skipped. Files MUST be non-null when empty.

### FLOW-019
Every selected content read, including SYSTEM.md, SPEC.md, the queued change, playbook and Files, MUST be contained through public SafePath before opening content; contained regular symlinks MAY succeed, while escapes, dangling links and missing descendants of escaping directories MUST fail without outside reads even if a later error would be ignored. Filesystem/Git enumeration errors MUST fail with corrective C01. Any failed BuildContext MUST return the zero WorkerContext with no partial files or metadata. Successful results and their nested maps/slices MUST be independent of inputs and repeated results, including immediately after mutation and on empty collections. Successes and rejections MUST remain local/noninteractive, preserve files/index/HEAD/branches/claim/other refs/common Git/user/ignored/outside files and parent cwd/environment/temp storage, and MUST NOT run hooks, agents, bootstrap or network commands, commit, stage, reset, fetch, push or create branches. Necessary read-only local Git inspection is allowed. Hook/agent commands from snapshots MUST NOT execute.

### FLOW-020
LoadApproval MUST accept only an exact valid claim slug and discover the canonical repository from start, including nested and linked checkouts. Invalid selectors MUST fail C05 before repository or content access. It MUST inspect only the exact selected shared claim ref, independently of other claims, and distinguish an absent ref from a malformed payload, symbolic alias or inspection failure. With no selected ref it MUST load the current project through public Load and return its metadata with a zero Claim. With a valid selected claim held by this canonical checkout it MUST load metadata from exactly Claim.Base through public LoadAt and return that exact Claim, including Object. Current config, module SPEC, queued/archive document bytes or moving/replacement refs MUST NOT replace this committed metadata. Both SHA-1 and SHA-256 repositories supported by installed Git MUST work.

### FLOW-021
In either source LoadApproval MUST select exactly one queued change by exact Slug and exactly one matching target module, and require its canonical immediate changes/ path to match the public filename grammar and slug. A selected archived change MUST NOT substitute for a missing queued change. For a claimed source it MUST parse Claim.State using that baseline path and target prefix, require a valid unchanged started document through public CheckState, and require its Module and Run to match the baseline target and Claim.Run, with phase evals/audit/impl. It MUST replace only that queued Change with the complete parsed approved record, retaining its assigned IDs, metadata, sections, path and order; all other baseline config, modules, changes, archive, diagnostics and BaseRef MUST remain as loaded. Initial late-ID/run/phase assignment and later committed phase states MUST both work. A missing or invalid current change MUST NOT prevent metadata restoration. It MUST NOT project preceding or selected changes itself; public Project/ApplyChange/BuildContext remain responsible for projection exactly once.

### FLOW-022
Missing/ambiguous queued selectors, missing/ambiguous target modules and invalid selected paths MUST fail with corrective C05; claim lookup/decoding, ownership, baseline loading or approved State/identity failures MUST fail with corrective P02 and preserve useful underlying public error details. Other discovery failures MUST retain corrective C01 details. A foreign-worktree, empty reservation, invalid started state, run/target mismatch, unavailable baseline, malformed selected ref or failed selected-ref inspection MUST NOT fall back to current metadata. HEAD differing from Claim.Base MUST NOT prevent read-only restoration: CheckWorktree separately rejects that mismatch before advancement. Every failed call MUST return a zero Snapshot and zero Claim, never partial metadata.

### FLOW-023
LoadApproval MUST remain local and noninteractive and preserve HEAD, branches, claim/other refs, index bytes, tracked/untracked/ignored/user/outside files, common Git and temporary storage, and parent cwd/environment on success and rejection. It MUST NOT commit, stage, reset, fetch, push, create branches, execute hooks/agents/bootstrap/network commands, or write files/refs. For a claimed source it MUST NOT open current config/SPEC/queue/archive contents, SYSTEM.md, playbooks, retained contracts/evals, disposable code or unrelated private contents; only necessary local Git metadata and committed source objects selected by LoadAt may be read. For an unclaimed source only the normal public Load discovery reads are permitted. Unsafe paths MUST reject before outside content opens, including ignored-error attempts. Returned snapshots and their nested maps/slices MUST be independent across repeated calls and after mutation, including empty append backing storage. Returning metadata alone MUST NOT execute coverage, boundaries or other project hooks, and MUST NOT validate current worker edits or change ownership.

### FLOW-024
Eligible MUST select exactly one queued change by an exact valid claim slug, rejecting invalid, missing or ambiguous selectors with corrective C05 and false. An archived-only selector MUST NOT substitute for a queued change. Queue precedence MUST be numeric Number ascending, then Slug and Path ascending, independently of supplied slice order and without sorting that slice in place. The selected change and preceding entries participate; later entries MUST NOT affect the result, except that a duplicate selected Slug remains an ambiguity. A selected blocked change MUST be ineligible. Ineligibility in an otherwise valid prefix MUST return false with nil error rather than inventing a failure diagnostic.

### FLOW-025
An unblocked selected change MUST be eligible only when no earlier runnable unblocked change exists and no earlier blocked change holds it. A blocked change holds a later change when they target the same module, when the later target depends directly or transitively on the blocked target, or when the later change has a nonempty Interface section and the blocked target depends directly or transitively on the later target. Earlier unblocked changes held by earlier blockers MUST be skipped rather than stop independent work; every earlier blocker MUST remain relevant, not only the nearest one. Later blockers MUST NOT hold earlier work. Multiple independently runnable changes MUST still have only the earliest eligible queue head. Empty or whitespace-only Interface bodies MUST NOT activate reverse dependency blocking, and other/fenced heading text MUST NOT substitute for the exact parsed Interface section.

### FLOW-026
For each candidate whose dependency relation is evaluated, Eligible MUST obtain its inclusive projected graph through public Project before that candidate and ApplyChange for the candidate exactly once. The selected inclusive graph MUST be validated even when the selected change is blocked or behind an earlier runnable head. This MUST include preceding set/depends_on changes, including blocked intent, and the candidate's own set values, while excluding later intent. It MUST use that graph for direct/transitive forward and Interface-dependent reverse relationships. Unknown or ambiguous target modules, missing dependency modules, self-dependencies, dependency cycles and failed prefix projection/application MUST fail atomically with corrective C05 and false, preserving useful public projection error details. It MUST NOT silently use an unprojected graph, ignore a failed projection, expand a cycle forever or treat a missing module as independent. This is essential graph/selection validation, not certification of all static project/queue requirements; unrelated hook/coverage/zone validation remains separate.

### FLOW-027
Eligible MUST operate only on supplied values outside any repository, remain local and noninteractive, and MUST NOT inspect files, Git, claims, hooks, agents, bootstrap, network, cwd or environment, or mutate files/refs/temporary storage or parent process state on success or rejection. Inputs and every nested map/slice/document MUST remain unchanged, including queue/module order and empty append backing storage, after successful and rejected repeated calls. The same supplied values MUST produce the same bool/error regardless of Root, current working directory or ambient files/environment. It MUST NOT allocate IDs, rewrite changes, apply specs to disk or run clean-tree, approval, coverage, boundary or worker-edit checks.

### FLOW-028
ApprovalMatches MUST parse currentText with the public change grammar at path using the supplied module prefix, require its target to equal module.Name, and return false with corrective C05 and useful public parser detail for invalid current input or target mismatch. Current input MUST be checked even when baseText is absent or malformed. Once current input is valid, empty, malformed or differently targeted baseText MUST return false with nil error. A valid content mismatch MUST also return false with nil error; a matching valid pair MUST return true with nil error. It MUST NOT certify static project validity, phase advancement, clean state, claim ownership, base provenance or queue eligibility.

### FLOW-029
After public Markdown normalization and handle mapping below, approval MUST compare the parsed authored Module, Set, Bases, Fixes, AlreadySatisfied and Regenerate metadata values, preamble, and ordered retained human/edit sections. Runtime Run, Phase and Blocked metadata and the exact sections Decisions, Questions, Audit, Provenance and Notes MUST be excluded. All other authored sections, including Motivation, Interface, Added, Modified, Removed, Removed decisions, Rejected alternatives and unknown names, MUST remain significant, including their names, order, tags, complete bodies and interior whitespace. Fenced headings and differently cased names MUST NOT become excluded sections. YAML key order, quoting/comments, CRLF and insignificant outer blank lines normalized by the public parser MUST NOT change approval. Omitted and explicitly empty top-level Set/Bases/Fixes/AlreadySatisfied collections MUST be equivalent; explicit empty values inside Set MUST remain significant. Ordered list values MUST NOT be silently sorted or treated as sets.

### FLOW-030
When both valid documents have the same number of Added items, every local Added handle in baseText MUST map positionally to the corresponding current Added ID or handle, and every occurrence of that declared handle in canonical metadata, preamble and retained section names/bodies MUST use that same binding before comparison. This MUST cover nested set hook strings, already_satisfied, Interface and fenced examples. Overlapping handle names MUST NOT corrupt one another, replacements MUST be simultaneous rather than cascade through another binding, and a base Added real ID MUST remain fixed. Differing Added counts or differing authored intent after this mapping MUST return false with nil error. This comparison MUST NOT allocate IDs, reserve numbers or infer approval merely from equal Added IDs or spec hashes.

### FLOW-031
ApprovalMatches MUST operate solely on supplied values outside a repository, remain deterministic/local/noninteractive, and MUST NOT inspect files, Git, claims, hooks, agents, bootstrap, network, cwd or environment, execute processes, allocate IDs or mutate files/refs/temporary storage or parent process state on success or rejection. It MUST preserve every supplied module field, nested map/slice/document and empty append backing storage after repeated true, false and error calls. Irrelevant module specs/zones/hooks/Decisions MUST NOT change its bool/error or trigger validation or execution. Ambient cwd/environment/files MUST NOT change results or error details.

### FLOW-032
Start MUST select one exact valid claim slug from the current repository's queued changes, discovering canonical ordinary or linked roots from nested start directories. Invalid selectors MUST fail with corrective C05 before repository access. Missing or ambiguous targets, invalid project/static queue metadata, unavailable source files and malformed selected state MUST fail with useful corrective diagnostics before creating a claim or changing working files. A dirty tracked, staged or untracked working tree MUST fail with corrective P01. Static warnings MUST remain visible on success. Start MUST use the current committed project and MUST NOT substitute a claim snapshot to bypass these preconditions.

### FLOW-033
Start MUST reject a blocked or otherwise ineligible selected change with corrective P03, using Eligible's complete inclusive queue semantics. Before starting, this canonical worktree MUST hold no existing claim, even for a different or no-longer-queued change. A selected claim held by another linked worktree MUST be rejected with corrective P02. A successful start MUST atomically create exactly one selected claim, recording canonical owner, exact slug, run and the full original HEAD commit. Concurrent competing starts MUST leave one winner; a loser MUST NOT alter the winner's claim or files. Malformed or unreadable existing claim metadata MUST fail closed with useful corrective P02.

### FLOW-034
For a fresh selected change, Start MUST use Allocate's late IDs and all-occurrence bindings, create a new nonempty run identity, and write run plus phase without committing. Spec changes and fixes MUST start in evals; maintenance and regenerate changes MUST start in impl. Different fresh runs MUST have different run identities. The saved started change, returned Context.Change and claim State MUST agree under public Markdown normalization, including retained author structure, metadata, typed edits and identity. The claim State MUST contain the exact saved change bytes. Allocation MUST retain removed/archived/previously assigned reservations and MUST NOT renumber unrelated changes.

### FLOW-035
For an eligible committed evals, audit or impl change with an existing run and no blocked field, Start MUST preserve its run, phase and every assigned ID while obtaining a new claim against current HEAD. It MUST NOT allocate new IDs or regress the phase. Removing blocked from a committed change MUST permit the same resume semantics. Incomplete run/phase pairs, applied queued state and unresolved local Added handles in a started change MUST fail before mutation. A claim alone MUST NOT make an uncommitted active worktree eligible for another start.

### FLOW-036
Start MUST return warning diagnostics P04 when HEAD does not contain the locally known base tip and independently when the selected authored content is absent or unapproved on that base. It MUST resolve the chosen base commit locally once, read the exact selected file from that pinned commit without replacement-object or lazy-fetch interpretation, and use ApprovalMatches against the started content so late IDs and canonical layout do not revoke approval. A malformed, different-target or absent base change MUST be unapproved. Unavailable base ancestry/content MUST never imply approval. Stale or unapproved content MUST warn rather than prevent an otherwise valid manual start. Base warnings MUST retain useful path and corrective guidance and MUST NOT change the configured base or any base ref.

### FLOW-037
On success Start MUST return a complete BuildContext result for the exact newly owned started state, including once-only projected zones/specs/dependencies and the playbook selected by BuildContext (regenerate takes precedence over phase), with a non-null Diagnostics array and the exact stored Claim including its object token. Failure to construct context, including an unsafe or unreadable required retained file or playbook override, MUST fail the whole start. Start MUST NOT certify a worker step, invoke verification hooks, run an agent or auditor, or advance beyond its initial or resumed phase.

### FLOW-038
Any failure after reservation MUST return a zero StartResult and roll back this operation's working-file writes/deletions and release only its own claim token. The selected change's original exact bytes and permission bits, and every deleted tracked file's contents/type/mode, MUST be restored when still owned by this operation. A replacement claim MUST survive rollback; a concurrently replaced change or recreated deleted path MUST NOT be overwritten. Lost ownership or incomplete rollback MUST produce useful corrective recovery details rather than falsely report a clean rollback. On success the selected change MUST retain its original permission bits. A selected change symlink or unsafe path MUST be rejected before mutation; temporary files MUST be cleaned after success and recoverable rejection.

### FLOW-039
For regenerate true without saved-attempt restoration, Start MUST delete only tracked files classified Disposable under the selected inclusive projected module zones. Protected, SPEC, eval, interface, append-only, preserved, other-module, other and ignored/untracked paths MUST survive, including stricter-zone overlap and metadata overrides. It MUST unlink a disposable leaf symlink without following or changing its target, reject unsafe symlink ancestors before deletion, and never recursively remove a directory containing retained files. Resume of a regenerate change MUST apply the same deletion rules. Start MUST return D01 warning when the target has no readable passing .fireweed/drills/<module>.md report whose base_commit is a locally known ancestor of HEAD with no reachable later target-module apply commit. Missing, malformed, failing, unavailable or stale reports MUST warn; a current passing report MUST suppress D01 even when later applies affect only other modules. Report content, dates and drill refs MUST remain unchanged.

### FLOW-040
Start MUST remain local, deterministic in all fields except fresh run identities, and noninteractive. It MUST NOT fetch, push, create branches/worktrees, commit, move HEAD, stage/reset the index, mutate other refs/claims, invoke Git hooks or fsmonitor, execute hooks/agents/bootstrap, use the network, or change parent cwd/environment. Ordinary and linked SHA-1/SHA-256 repositories MUST retain all unrelated tracked/ignored files, file modes, index bytes, refs, common-Git bookkeeping, attempts and drill reports. Failure paths MUST preserve the same unrelated state. The operation MUST use bounded local subprocesses and retain useful failed-command details without parsing stderr as a successful Git stdout protocol.

### FLOW-041
Verify MUST validate a nonempty explicit slug before repository access, rejecting invalid selectors with corrective C05. It MUST discover the canonical checkout from start, select the exact named held claim or the unique claim owned by this checkout when slug is empty, and reject missing, ambiguous, malformed or foreign selected ownership with corrective P02. Explicit selection MUST remain independent of malformed unrelated claim payloads. It MUST restore the selected approved snapshot and exact started State from the claim's committed Base through LoadApproval, never use current worker configuration/SPEC/queue metadata as authority or silently fall back to unclaimed source. Fatal selection/source failures MUST return a zero Verification and useful non-nil error. Valid ordinary and linked SHA-1/SHA-256 worktrees MUST work from nested start paths.

### FLOW-042
For a valid selection Verify MUST use Project before the selected change and ApplyChange for that change exactly once, including preceding queued effects and the selected set while excluding later effects. It MUST validate the resulting effective project and dependency graph before executing hooks. It MUST compose CheckWorktree with that inclusive approved target and preserve its actual Edits and independent diagnostics. Invalid graph, approved worker state, ownership, HEAD, edit zones or path containment MUST prevent all verification hooks; current blocked MUST add corrective P05 and also prevent hooks. Invalid current change text or unsafe/unreadable current paths MUST fail closed through the existing guards. Structured checking failures MUST return initialized Verification data with nil error, preserving Change/Phase from approval, non-null Diagnostics/Coverage/Edits and useful diagnostics; source failure remains governed by FLOW-041.

### FLOW-043
In evals Verify MUST evaluate exactly the selected inclusive target module with the approved effective hooks/configuration through public Evaluate. Fail-first targets MUST include every Added, Modified and fixes ID, with approved already_satisfied passed under public coverage policy. Coverage, hook status/output, testcase data and all coverage diagnostics MUST remain visible even for expected fail-first failures, unrelated failures, missing/malformed reports or hook errors. It MUST NOT evaluate dependent modules or run boundaries during evals, and MUST NOT treat worker-modified hooks or metadata as approved. Removed IDs MUST remain absent from the projected coverage contract. Legitimately passing fail-first checks MUST yield no verification errors.

### FLOW-044

[approved-state]
This is a text-state guard, not full lifecycle verification: filesystem zones, symlinks, HEAD/claim ownership, questions/block transitions, fail-first, audit completeness and hook execution remain separate composition. Input module identity is the resolved target from the approved snapshot. Public ParseChange owns grammar and normalized document values; the guard owns permission comparison. [phase-permissions]
This pure policy consumes the approved projected target, rather than deriving zones from worker-edited change metadata. Lifecycle composition will obtain that target through Project/ApplyChange before calling it. This API does not validate live claims, HEAD, symlink containment or actual edit collection; those remain a separate checked worktree operation. CheckState owns current-change body/metadata restrictions.

[local-claims]
This is claim storage, not queue eligibility, one-change-per-worktree policy, approval validation or phase transitions. No fireweed enforcement hook is changed or bypassed in this rebuild.

Update compares the supplied previous record with the actual stored record before a compare-and-swap, then Git enforces the final atomic token check. A content-identical update naturally retains its object ID. Explicit ReleaseClaim is an ownership-token operation rather than an owner-only action, matching manual release intent while preventing a stale release from deleting a newer claim. Git errors carry P02 plus a corrective action; callers never receive partial successful data.

[live-worktree]
The caller owns static project validation and selection/projection; this guard never trusts a worker-edited phase or set for permissions. Protected config/SPEC changes remain rejected by the global file policy even if a caller reloads a current snapshot. Only a passing aggregate guard can lead to later hook execution. CheckState owns normalized intent, CheckEdits owns phase zones, claim storage owns exact owner/token records and Git primitives own edit/path semantics.
