# workflow

## Specs

### FLOW-001
CheckState MUST parse approved and current text with the public change grammar, using the supplied module's ID prefix and the supplied change path. An invalid approved document, an approved target different from the supplied module name, a missing run, or an approved phase outside evals/audit/impl MUST return a P02 error at that path with corrective claim guidance. Once approval is valid, invalid current text MUST return P2-01 at that path with corrective worker-edit guidance. Invalid state MUST NOT be accepted as an unchanged change. A valid unchanged started change, including maintenance and regenerate changes, MUST return an empty non-null diagnostic slice.

### FLOW-002
CheckState MUST reject semantic changes to every approved metadata field except blocked with P2-01, including module, nested set/hook/zone values, bases, fixes, already_satisfied, regenerate, run and phase, and adding or removing metadata keys. Valid blocked reasons MAY be added, replaced or removed. For an approved evals or impl phase it MUST permit adding, changing, moving or removing Decisions, Questions and Notes sections; for an approved audit phase it MUST permit only Audit and Questions sections. Every other parsed section, its body and relative order, and the parsed preamble MUST remain unchanged. Protected edits MUST yield P2-01, including Motivation, Interface, Added/Modified/Removed, Removed decisions, Rejected alternatives, Provenance, unknown sections and changes hidden after duplicate or fenced headings. Permissions MUST derive from the approved phase even when current metadata attempts to switch phase. Metadata ordering/quoting and line-ending changes with the same public parsed values MUST NOT be rejected. Exact case-sensitive section names and public fenced-Markdown parsing MUST determine permissions rather than substring replacement.

### FLOW-003
CheckState MUST return fresh non-null diagnostics sorted deterministically by Path, Code, Severity and Message, with severity error, the supplied path and nonempty corrective messages for every rejection. Metadata and protected-body violations in the same valid current document MUST both remain visible; invalid approved or current grammar MUST stop that comparison rather than inventing partial acceptance. Results, including writable empty results, MUST remain independent across repeated calls, and supplied module fields/maps/slices and input strings MUST remain unchanged. It MUST work from supplied text outside any repository, remain noninteractive and MUST NOT create or edit files/refs, execute Git, hooks, agents, the bootstrap or network commands on successful or rejected calls.

### FLOW-004
CheckEdits MUST use the supplied approved module's projected zones in preference to the snapshot's stale selected-module zones, and repository-relative ownership from every other snapshot module. It MUST reject protected paths, every basename SPEC.md, other modules' paths and every changes/ path except a modification of the exact current change with P2-01. worker_writable MUST permit only otherwise unowned paths and MUST NOT override protected, spec, other-module or other-change restrictions. Exact current-change modifications MUST be allowed for all worker phases; CheckState separately enforces its content. Paths outside modules and worker_writable MUST be rejected with P2-01. Prefix-similar module/change paths MUST NOT be mistaken for owned or current paths.

### FLOW-005
For an approved evals phase, CheckEdits MUST permit target evals, other module files such as manifests, permitted worker_writable paths, and new disposable files only. Interface edits MUST require a nonempty exact Interface section in the approved change, otherwise returning P1-01. Preserved and append-only additions or edits, and modification, deletion, type change or rename of disposable files MUST return P1-01. Both source and destination of every rename MUST be checked against their own zones and owners, so moving protected, other-module, eval, interface, preserved, append-only or existing disposable files cannot evade their phase restrictions. A copy's source is unchanged: it MUST have a valid path but MUST NOT be treated as an edit; its destination MUST be checked as a new addition.

### FLOW-006
For an approved impl phase, CheckEdits MUST permit target disposable, preserved and other module files and permitted worker_writable paths, but reject every target eval or interface addition, modification, deletion, type change or rename with P2-01. For audit, it MUST reject every edit except modification of the exact current change with P2-01. Independently of phase and zone precedence, every modified, deleted, type-changed or renamed endpoint matching any owning module's append_only glob MUST return H03, including overlaps with stricter zones and edits to other modules. Append-only destinations of additions or copies MAY be accepted in impl when other restrictions permit; evals MUST reject them with P1-01. All independent H03 and phase/ownership violations MUST remain visible at their own paths.

### FLOW-007
CheckEdits MUST reject a missing run, mismatched approved target or approved phase outside evals/audit/impl with P02 at the current change path and corrective guidance, stopping file-policy comparison. It MUST reject malformed edits with P2-01: only A/M/D/T/R/C statuses are accepted; all paths MUST be canonical slash-separated repository-relative file paths without empty, dot, parent, absolute, backslash or NUL components; R/C MUST have a distinct valid OldPath and other statuses MUST NOT have OldPath. It MUST return fresh non-null diagnostics sorted by Path, Code, Severity and Message, deduplicating identical diagnostics, with severity error and nonempty corrective messages. Inputs, nested maps/slices and earlier results MUST remain unchanged, including immediately after result mutation and on rejected calls. Successful and rejected calls MUST remain noninteractive outside a repository and MUST NOT read or mutate files/refs, run Git, hooks, agents, the bootstrap or network commands, or change parent cwd/environment.

### FLOW-008
CreateClaim MUST store a JSON blob at refs/fireweed/claims/<slug> using an atomic create-only Git ref update, with the canonical current worktree root, exact slug/run/state and a full resolved local commit ID for Base. It MUST return that stored Claim and its full blob Object token, without committing or moving HEAD. Only nonempty slugs matching lowercase letters/digits followed by lowercase letters/digits/hyphens and a nonblank run are valid; invalid slugs, missing runs, unavailable repositories and unresolvable commit bases MUST fail with P02 and corrective guidance and create no claim. Empty State MUST be allowed as an initial reservation. Competing creates for the same slug, including from linked worktrees, MUST have exactly one winner; a conflict MUST preserve the winner and report its ownership/release guidance. Different slugs MUST remain independent.

### FLOW-009
UpdateClaim MUST require the exact current Claim, including its Object token, held by the calling canonical worktree; it MUST preserve Worktree, Change and Run, replace State exactly, resolve the new Base to a full local commit ID and atomically replace only the expected blob ref. A stale, modified or foreign-worktree previous Claim MUST fail with P02 and corrective guidance without overwriting current ownership. ReleaseClaim MUST atomically delete only the named ref matching the supplied full Object token, and MUST reject missing/stale/invalid tokens or missing claims with P02 and corrective guidance. Explicit release MAY be performed from another linked worktree; it MUST NOT delete a replacement claim. Updates and releases racing on one token MUST NOT both succeed, except that a genuinely unchanged update MAY retain the same content-addressed token.

### FLOW-010
LoadClaim MUST read the exact shared claim ref, return its complete independent stored fields and full Object token, and reject missing refs, non-blob objects, malformed JSON, trailing JSON values, missing or incorrectly typed required fields, invalid slug/run/worktree/base values and stored Change differing from the requested slug with P02 and corrective guidance. Worktree MUST be an absolute clean path, but its directory MAY no longer exist so stale claims remain inspectable. Claims MUST list every shared claim in ascending Change order, excluding unrelated refs; an empty inventory MUST be non-null. It MUST reject malformed claim refs or payloads atomically rather than silently skipping them or returning a partial inventory. Failed Claim-returning calls MUST return a zero Claim, and separate returned inventories/claims MUST remain independent.

### FLOW-011
Every claim operation MUST remain local and noninteractive, use literal Git arguments, and MUST NOT run fireweed hooks, native Git ref-transaction hooks, agents, the bootstrap or network commands. Successes and rejections MUST preserve HEAD, branches, the caller's index, working files, ignored/user files, other refs, input Claim values, parent cwd and environment; only the selected claim ref and necessary Git object storage MAY change. Temporary owned storage MUST be cleaned on success and failure, including duplicate-create and stale-update failures. Reads and failed precondition checks MUST NOT change refs. Claims MUST work across linked worktrees and in SHA-1 and SHA-256 repositories supported by installed Git, without a hard-coded object-ID width. Claim operations MUST NOT fetch, push, create branches or require author identity, authenticated agents or network access.

### FLOW-012
CheckWorktree MUST discover the canonical checkout from snapshot.Root, require the exact current stored Claim including Object and fields, require that claim's owner to be this checkout, and require HEAD to equal Claim.Base. It MUST validate Claim.State as an unchanged valid started document through CheckState and public change grammar, with parsed Module, Run and Slug agreeing with the supplied module and Claim. changePath MUST name that queued change directly under changes/, never an archive or escaping/invalid path. Unavailable repositories, missing/stale/tampered/foreign claims, moved HEAD or invalid approved state/identity/path MUST return a corrective P02 at changePath, empty non-null Edits, and stop before current-file comparison or edit collection. Linked worktrees and SHA-1/SHA-256 claim records MUST be supported without changing HEAD or ownership.

### FLOW-013
After valid preconditions, CheckWorktree MUST read the exact current change only after checking its path's containment with the public SafePath contract. Missing, unreadable, directory or escaping/dangling-symlink current changes MUST produce corrective P2-01 at changePath; escaping file contents MUST NOT be read even when read errors would be ignored. Safe in-repository links MAY be read, but their actual type-change edits MUST still obey CheckEdits. Valid current text MUST be compared with Claim.State through CheckState, using the approved phase rather than worker-modified metadata. Invalid current grammar, immutable metadata or protected body edits MUST retain those exact public state diagnostics. Allowed worker prose and blocked edits MUST remain permitted by this guard; blocking/Questions policy is separate.

### FLOW-014
With valid preconditions, CheckWorktree MUST collect the public Git Edits since the exact Claim.Base, including staged, unstaged and untracked files and preserving rename source/destination records. Collection failures MUST return corrective P02 at changePath. It MUST check containment of every edit destination and every rename/copy source, recording corrective P2-01 at each unsafe endpoint, including nonexisting descendants of escaping directory symlinks. It MUST compose CheckEdits using the supplied approved projected target and validated snapshot, retaining independent state, safety and phase/ownership/append-only violations instead of accepting edits after one check fails. Normal permitted changes MUST pass; protected/global/spec/foreign/other-change edits, impl eval/interface renames and evals existing disposable edits MUST fail through the established public policy. No coverage, boundary hook or agent MUST run in this operation.

### FLOW-015
CheckWorktree MUST return fresh non-null Edits and Diagnostics with diagnostics deduplicated and sorted by Path, Code, Severity and Message. Errors MUST have severity error, their specified path and nonempty corrective guidance. Repeated results, including empty results, and input snapshots/modules/claims/maps/slices MUST remain independent and unchanged immediately after result mutation, on successes and rejections. The operation MUST remain local and noninteractive, preserve HEAD, branches, claim/other refs, index bytes, tracked/untracked/ignored/user files, private outside files and parent cwd/environment, and MUST NOT commit, reset, stage, fetch, push, create branches, execute hooks/agents/bootstrap/network commands or leave owned temporary storage. It MAY perform necessary local read-only Git/filesystem inspection. Supplied snapshots' hook/agent strings MUST NOT be executed even on success or failure.

### FLOW-016
BuildContext MUST select exactly one queued change by its exact Slug from the supplied approved snapshot, reject missing/ambiguous selectors, missing target modules, invalid queued paths or phases outside empty/evals/audit/impl with corrective C05, and return that independent Change. The queued path MUST be directly under changes/ and have the selected slug under the public change filename grammar. It MUST obtain the target Module by projecting all preceding queued changes through public Project and applying the selected change through public ApplyChange, including current specs, metadata, zones and Decisions behavior of those APIs. Later changes MUST NOT affect it. Dependencies MUST contain only that projected target's direct dependencies, in declared order, using modules from the preceding projection; missing dependencies MUST fail C05. Empty Dependencies MUST be non-null. Selection/phase/path/projection errors MUST stop before repository/file access. The caller supplies an approved snapshot; this operation does not reload worker-modified config or module metadata.

### FLOW-017
BuildContext MUST discover the canonical repository from snapshot.Root and return its canonical GitCommonDir, supporting nested roots and linked checkouts. It MUST return exact current queued ChangeText, exact current target SPEC.md as SpecText and exact SYSTEM.md as System, preserving frontmatter, CRLF, empty contents and missing final newlines. A missing SYSTEM.md MUST produce empty System; other system/spec/current-change read failures MUST fail C01 with a corrective path-attributed error. A missing current change MAY use only the exact State from a valid stored claim owned by this canonical checkout whose Change, Run, parsed target and phase match the selected started change; otherwise it MUST fail C01. Unsafe paths MUST fail before content opens and MUST NOT fall back through a claim. It MUST select author-change for an empty phase, otherwise the selected phase, with regenerate taking precedence when Regenerate is true; public ResolvePlaybook MUST provide exact Playbook and PlaybookHash, including overrides, empty text and stale/malformed metadata without new warnings. Resolver errors MUST retain their public corrective details.

### FLOW-018
BuildContext MUST enumerate current tracked and untracked nonignored repository files through local Git, deduplicate and sort Files by repository-relative slash Path and preserve exact content bytes. Tracked ignored files MUST remain eligible; untracked ignored files MUST be excluded. In every phase it MUST include only the target's eval and interface files; outside audit it MUST additionally include target preserved/append-only files and direct dependency interface files. Selection MUST use the projected target zones, preceding projected dependency zones and public ZoneFor precedence with configured protected paths. Audit MUST exclude preserved/append-only and dependency interface contents. Disposable, other/manifest, unrelated module, transitive-only dependency, worker_writable-only, protected and SPEC.md files MUST NOT appear in Files or have their contents read by this enumeration. Missing tracked selected files, unreadable selected files, directories and unsafe/dangling selected paths MUST fail C01 rather than being silently skipped. Files MUST be non-null when empty.

### FLOW-019
Every selected content read, including SYSTEM.md, SPEC.md, the queued change, playbook and Files, MUST be contained through public SafePath before opening content; contained regular symlinks MAY succeed, while escapes, dangling links and missing descendants of escaping directories MUST fail without outside reads even if a later error would be ignored. Filesystem/Git enumeration errors MUST fail with corrective C01. Any failed BuildContext MUST return the zero WorkerContext with no partial files or metadata. Successful results and their nested maps/slices MUST be independent of inputs and repeated results, including immediately after mutation and on empty collections. Successes and rejections MUST remain local/noninteractive, preserve files/index/HEAD/branches/claim/other refs/common Git/user/ignored/outside files and parent cwd/environment/temp storage, and MUST NOT run hooks, agents, bootstrap or network commands, commit, stage, reset, fetch, push or create branches. Necessary read-only local Git inspection is allowed. Hook/agent commands from snapshots MUST NOT execute.

## Decisions

[approved-state]
This is a text-state guard, not full lifecycle verification: filesystem zones, symlinks, HEAD/claim ownership, questions/block transitions, fail-first, audit completeness and hook execution remain separate composition. Input module identity is the resolved target from the approved snapshot. Public ParseChange owns grammar and normalized document values; the guard owns permission comparison. It compares parsed metadata keys and nested values, so adding an explicit empty immutable key is still a metadata edit. blocked alone is mutable metadata. Approved started state must have a run and a recognized worker phase; applied/queued state is not a live step baseline.

The approved phase selects section permissions, so an auditor cannot grant itself implementation permissions by changing phase. Non-audit workers may edit Notes as well as Decisions/Questions, matching the reference's documented free-prose workflow. All occurrences of an allowed section are mutable only when public grammar accepts them; every retained protected section occurrence remains compared. Unknown sections and the preamble remain protected. Parser-normalized whitespace and YAML syntax are not independent approval fields. A metadata violation and a protected-body violation produce separate diagnostics, in stable order; invalid text produces one parse/baseline diagnostic first.

The initial incomplete cycle was fully reverted before this restart (D017). Temporary cwd fixtures must resolve filesystem aliases before comparing with os.Getwd; establish that premise independently. The public guard must preserve actual parent state, rather than manipulating cwd or environment to satisfy a raw alias string. Duplicate-heading invalid-input cases use raw text because the document renderer correctly rejects duplicate sections before the state guard.

[phase-permissions]
This pure policy consumes the approved projected target, rather than deriving zones from worker-edited change metadata. Lifecycle composition will obtain that target through Project/ApplyChange before calling it. Snapshot ownership is already statically validated; stale target zones are replaced, while foreign module ownership/append-only rules remain effective. This API does not validate live claims, HEAD, symlink containment or actual edit collection; those remain a separate checked worktree operation. CheckState owns current-change body/metadata restrictions.

A rename's original R status applies to both endpoints. Evals cannot rename an existing disposable file into or out of a stub path, and implementation cannot rename a retained eval/interface away. Copies leave their source unchanged and check destination additions. Append-only H03 is independently visible even when stricter worker-zone rules reject the same endpoint. Evals keeps append-only read-only, including additions; implementation permits only additions/copy destinations. Every basename SPEC.md is controller-owned, including nested/outside-module paths. Current-change exemption permits only ordinary M, never deletion, type change, copy or rename.

[local-claims]
This is claim storage, not queue eligibility, one-change-per-worktree policy, approval validation or phase transitions. Start will reserve with empty State before assigning IDs and then update its approved text. Update can move Base after a controller-owned phase commit; a later live-worktree guard checks HEAD against that baseline. Base input may name any locally resolvable commit and is normalized to its full object ID. State is opaque text here; CheckState owns started-document grammar and worker permissions.

Stored JSON consists of the five required string fields. Additional JSON fields are tolerated for forward-compatible reference data; unknown fields do not replace required validation. Empty State is valid. Run is preserved byte-for-byte when nonblank. Load validates Base names as full stored commit IDs and checks local existence; it does not require the stale owner's directory to exist. Git's native reference-transaction hooks are disabled for these metadata operations, so claiming cannot run unrelated project hooks. No fireweed enforcement hook is changed or bypassed in this rebuild.

Update compares the supplied previous record with the actual stored record before a compare-and-swap, then Git enforces the final atomic token check. A content-identical update naturally retains its object ID. Explicit ReleaseClaim is an ownership-token operation rather than an owner-only action, matching manual release intent while preventing a stale release from deleting a newer claim. Unreachable blob objects left by a lost ref race are normal Git object storage, not leaked temporary files. Git errors carry P02 plus a corrective action; callers never receive partial successful data.

[live-worktree]
The caller owns static project validation and selection/projection; this guard never trusts a worker-edited phase or set for permissions. Protected config/SPEC changes remain rejected by the global file policy even if a caller reloads a current snapshot. Only a passing aggregate guard can lead to later hook execution. CheckState owns normalized intent, CheckEdits owns phase zones, claim storage owns exact owner/token records and Git primitives own edit/path semantics. This change does not start, advance, block or apply a change and never updates a claim.

Precondition failures return one P02 before collecting edits or reading the current change. Once preconditions pass, edit collection and safety/file policy remain useful even when the current change is missing or invalid, so diagnostics compose; a collection failure is P02 and cannot imply a clean tree. Endpoint safety rejects attempted operations on escaping paths without following outside file contents. Deleting a missing source remains governed by the existing SafePath contract and phase policy. Results expose the actual Git edit records without synthesizing a different rename representation. Error messages from public CheckState and CheckEdits remain intact.

[worker-context]
This API consumes an approved captured snapshot, like CheckWorktree; later lifecycle/CLI composition owns capture/approval and current-edit rejection. It does not execute hooks or validate a live step for advancement. Change remains the approved typed record while ChangeText exposes current exact bytes for worker feedback. Missing-change recovery uses the owned matching claim only; other read failures are actionable errors. SYSTEM.md absence matches standalone/minimal project context, while target SPEC.md and selected retained files are required. Atomic zero results prevent partial context being mistaken for success.

Projected context includes preceding queued effects and the selected change, but no later effects. Direct dependency metadata/zones come from the preceding projection and are not recursively expanded. Files contain only phase-selected retained text; manifests and worker_writable files are writable permissions rather than automatic prompt content. Git tracked-plus-untracked enumeration includes new stubs/retained contracts but excludes ignored scratch and binaries. All explicit source reads use contained regular files. These safeguards extend the ordinary reference context behavior, which silently ignores several selected read errors; no real regeneration is claimed by constructing a context.
